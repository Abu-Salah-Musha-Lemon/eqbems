# Glossary

| Term | Meaning |
|---|---|
| Academic context | Institution, period/program/subject scope under which content or an exam is managed |
| Blueprint | Rules that specify question counts, marks, topics/difficulty distribution, and total exam constraints |
| Candidate | Student or other participant registered for an examination |
| Exam snapshot | Immutable copy/reference of exact question versions and paper structure used for a particular exam version |
| Institution | School, college, university, or organization using EQBEMS; exact hierarchy depends on the tenancy decision |
| Organization | Potential parent tenant grouping institutions; currently not represented by a corresponding table in migrations |
| Permission | Specific allowed action such as `institution.create`; must be checked server-side |
| RBAC | Role-based access control; users receive permissions through roles, with any direct grants explicitly governed |
| Question version | Immutable approved or historical content revision of a reusable question |
| Review state | Workflow state such as draft, submitted, approved, changes requested, rejected, or retired |
| Tenant scope | Organization/institution boundary used to restrict data access |
| Verified feature | Feature meets its acceptance criteria, tests pass, and the evidence/environment is recorded |
| V1 / V2 | Product release targets, not branch names and not claims that feature code exists |
